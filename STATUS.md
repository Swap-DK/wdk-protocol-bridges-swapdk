## In flight

- **E2E BTC source mainnet validation** — gates the upstream PR to `tetherto/wdk-wallet-btc`. Plan: small BTC → ETH swap via the example CLI; once `waitForBridge` returns `completed`, push the upstream PR from the artifacts in `wdk-wallets-swapdk/packages/btc/docs/upstream-pr/`.

## Blocked

- **TRON source module** — two-layer blocker. (1) swap-engine doesn't recognise TRON as a source chain (`utils/swap_engine.go` dispatch covers EVM / UTXO / Cosmos only); a `POST /quote` for `TRON.TRX` returns `unsupported sell chain`. (2) `@tetherto/wdk-wallet-tron@1.0.0-beta.5` exposes only plain TRX transfers and hardcoded TRC-20 `transfer(address,uint256)` — no path to call the THORChain TRON router's `depositWithExpiry`. Full research: [`packages/evm/docs/research-tron-source.md`](./packages/evm/docs/research-tron-source.md).
- **Trade-asset deposits on THORChain / MAYAChain** — fees and decimals fall back to chain-native defaults; correct handling needs an asset-registry extension. Not on near-term roadmap.

## Recently shipped

- **2026-06-16** — `swap-engine-client@0.2.0` (renamed from `bridge-swapdk-common@0.1.11`) + cascade patch bumps to all five bridge packages. Two coordinated changes:
  - **Rename.** `@swapdk/wdk-protocol-bridge-swapdk-common` → `@swapdk/swap-engine-client`. Drops the `"internal"` keyword and the "Not intended to be consumed directly" framing — the package is now first-class shared infrastructure consumed by both distribution channels (WDK bridges here + the wagmi-native `@swapdk/wagmidk`). All five bridge packages cascade-update their `dependencies` to the new name (existing internal imports replaced via grep+sed). Public re-export shape of each bridge is unchanged — consumers continue to see `SwapDKClient`, `KnownToken`, etc. via their bridge package.
  - **zod validation at the HTTP boundary.** `http-types.ts` rewritten as `http-schemas.ts`: zod schemas are now the source of truth, types derived via `z.infer<typeof Schema>`. `SwapDKClient` calls `.safeParse()` on every `/quote`, `/swap`, `/track`, `/chainflip/broker/channel` response and throws `SwapDKApiError(errorCode: "response_schema_mismatch", cause: ZodError)` on shape mismatch — pointing to the first failed field path for quick debugging. WDK bridges inherit this validation transitively without code changes.
  - Rationale and full ADR text lives in the wagmidk repo: `../wagmidk/docs/adr/ADR-008-swap-engine-client-rename.md`, `../wagmidk/docs/adr/ADR-009-zod-http-validation.md`. No corresponding ADR set in this repo (adr-kit not adopted here); this STATUS entry is the authoritative pointer.
  - One-time behavioural change: edge cases where swap-engine previously returned malformed responses that `as`-cast tolerated will now throw `SwapDKApiError` at the boundary. Strictly an improvement (loud failure > silent corruption); operators should monitor for `response_schema_mismatch` errorCodes on first deploy and report any genuine swap-engine shape drift back to the swap-engine team.
- **2026-05-25** — `bridge-swapdk-tron@0.1.0`: initial scaffold. Wraps the swap-engine TRON dispatch (shipped earlier in `fc0721e`) for source-side BTC bridge consumers — TRX + TRC-20 USDT → any THORChain destination. Mirrors the EVM bridge module's router-contract flow with TRON-specific envelope (`callValue` + `feeLimit` in SUN, base58 addresses). Optional approval tx for TRC-20. 21 vitest cases cover WDK contract, source-token forms, TRX/TRC-20 happy paths, stale-route retry, bridgeMaxFee, /track default chainId. Pending: E2E mainnet validation (THORChain pool for TRX → ETH live?). Consumes `@swapdk/wdk-wallet-tron@0.1.0` (file: link).
- **2026-05-25** — `bridge-swapdk-common@0.1.5`: optional `feeLimit?: string` on `SwapTx` / `ApprovalTx` HTTP types — surfaces the SUN energy cap swap-engine attaches to TRON contract calls. Backwards-compatible.
- **2026-05-22** — `bridge-swapdk-common@0.1.4`: `SwapDKApiError.isAmountBelowMin` getter now also matches `/quote` + `quote_amount_below_min`, the path-specific errorCode swap-engine emits when Chainflip rejects a BTC quote below its broker minimum (since Chainflip retains sub-minimum deposits without refund). The existing `/swap` + `swap_amount_below_min` match is preserved. CLI's `handleSwapError` automatically renders the new path with the existing "Amount below upstream minimum" message — no changes downstream of the common bump required.
- **2026-05-22** — `bridge-swapdk-btc@0.2.0`: dispatch by provider — Chainflip is now a first-class second flow alongside THORChain / MAYAChain. New `SwapDKBridgeBtc.bridgeViaChainflip()` opens a deposit channel via `client.openBrokerChannel()` and broadcasts a plain BTC tx (no OP_RETURN). `SwapDKBridgeResult` gains `provider` (always populated) and `depositAddress` + `channelId` (Chainflip only). `SwapDKBridgeOptions` gains 6 optional Chainflip fields (refund triplet, DCA pair, boost cap); ignored on THORChain routes. `trackBridge` / `waitForBridge` accept `depositAddress`. The 0.1.1 provider filter is removed — `pickBestRoute` ranks all providers by output. Research: [`packages/btc/docs/research-btc-chainflip-source.md`](./packages/btc/docs/research-btc-chainflip-source.md). Same cycle also fixes a long-standing `resolveAssetDecimals` bug in `packages/btc/src/asset-map.ts` (was passing SwapKit prefix `"ETH"` to `lookupToken` instead of the WDK chain name `"ethereum"` — registry miss made USDC fees fall back to 18-decimals and surface as ~`1.6×10^17` instead of `0.16` USDC). New `bridgeFeeAsset?: string` field on both result types surfaces the fee currency so callers can format it correctly.
- **2026-05-21** — `bridge-swapdk-common@0.1.3`: additive HTTP-types surface for Chainflip BTC source. `TrackRequest` gains optional `depositAddress` (matches swap-engine's `Models.TrackRequest.DepositAddress` added for the Chainflip `/track` fallback). New types: `BrokerChannelRequest`/`Response`, `ChainflipAsset`, plus refund/DCA/metadata/affiliate sub-types. New method: `SwapDKClient.openBrokerChannel(req)` → POST `/chainflip/broker/channel`. No breaking changes; existing EVM / Cosmos / Solana / BTC bridges keep their wire shape byte-for-byte.
- **2026-05-21** — `bridge-swapdk-btc@0.1.1`: filter `quoteBridge` results to THORChain / MAYAChain providers only. Surface: when THORChain is halted, swap-engine falls back to Chainflip, which on BTC source uses a deposit-channel model (no OP_RETURN, different fee shape) the module can't broadcast. Previously the quote returned a degraded result with empty `inboundAddress`/`memo`; `bridge()` would have failed but `quote()` was misleading. Now: `quote()` throws `SwapDKUserError` upfront with the provider name. THORChain routes still win even when Chainflip's `expectedBuyAmount` is higher.
